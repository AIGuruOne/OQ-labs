# facilitator/ — what is in here and when it is used

Everything the facilitator hands out or shows. Slides are Ritesh's
(`slides/`); the rest is engineered here and lives in git so the
numbers in it can be traced to a run.

## Day 1 paper artifacts (P12)

These are what participants leave Day 1 with. One scaffold plus five
briefs, not five starter kits (BUILD_SPEC section 14).

| File | Session | Minutes | What it is |
|---|---|---|---|
| `decision_matrix_template.md` | S3, 11:15 | 12 of the 35 | Build / buy / host: five gates, four options, eight weighted criteria with scoring guidance, the five-sentence defence, and a worked example for the ticket triage case with the arithmetic shown |
| `architecture_spec_template.md` | S4, 12:45 | 75 of the 90 | Ten sections, prompts not blank boxes, minute budget per section. A filled one is deployment-relevant; see the example |
| `cost_model.xlsx` + `cost_model.md` | S4 | 10 of the 90 | Volume and tokens in, $ per month out, vendor API against self-hosted, break-even and idle share. Every price cited and dated; regenerated by `scripts/build_cost_model.py` |
| `spec_review_checklist.md` | S5, 14:30 | 25 | 43 YES / NO / CAN'T TELL questions grouped by spec section, the manager's three questions, a three-finding block with severities, and a clock |
| `use_case_briefs.md` | S4 hand-out; close, 14:55 | 20 | Five capstone briefs: problem, who feels it, success, data in the repo, what deployment-ready means, which sessions supply what, what to show on Thursday. Brief 1 is the locked fine-tune task |
| `examples/architecture_spec_brief1_filled.md` | reference | — | The spec template filled for brief 1 in a notional 90 minutes, with real eval and cost numbers from this repo |
| `examples/spec_review_brief1_filled.md` | reference | — | The checklist applied to that spec: three findings, two of them blocking, all genuine |

Order on the day: matrix (S3) → briefs handed out, spec written with
the cost model (S4) → specs swapped and reviewed (S5) → groups
confirmed (close). The spec is revised that evening (v0.2) and again
on Day 2 with the S12 eval numbers (v0.3).

## Day 5 governance pack (P14)

`governance_pack/` — eight fillable templates for S29 (12:45, 30
minutes, talk and template) and a worked example. Its README has the
minute-by-minute split of what Ritesh presents and what the groups
fill in the room (template 1 and the tool table of template 4) versus
take away. `governance_pack/sources.md` is the list of every framework
and regulation the templates cite, with links and how each was
verified; nothing is cited from memory.

| File | Minutes | What it is |
|---|---|---|
| `governance_pack/01_system_register.md` | 8 | What the system is, who owns it, what it touches, what a wrong output does, autonomy level, risk tier |
| `governance_pack/02_data_classification.md` | 12 | Every copy of the data, one row each; self-hosted VM versus vendor through the tenant versus vendor direct, with the vendor retention facts cited |
| `governance_pack/03_evaluation_acceptance.md` | 12 | The eval as an acceptance bar: four measurements, the eval set's provenance, behaviour tests shown not described, the shadow period |
| `governance_pack/04_approval_gating.md` | 12 | Action classes R / W1 / W2 / X, the tool table with MCP annotations and the gate location, what the approver must see, never-automated list, kill switch |
| `governance_pack/05_audit_logging.md` | 8 | The three event lines (`llm_call`, `tool_call` as the S26 server writes it, `index_write`), where the log lives, the two reconstruction queries |
| `governance_pack/06_incident_response.md` | 12 | Severities, the first hour, and the runbook for a confidently wrong extraction in the knowledge base (the Day 3 case) |
| `governance_pack/07_change_management.md` | 8 | What is versioned (model, adapter, prompt, schema, index build, thresholds, tools), the promotion rule, the rollback drill |
| `governance_pack/08_monitoring_drift.md` | 8 | The weekly numbers with thresholds and the runbook each starts; drift signals; automation bias |
| `governance_pack/examples/brief3_vision_capture_filled.md` | — | The pack filled for brief 3 (nameplate and diagram capture): the brief that has the known-bad extraction, the gated ERP write and the index write. Extraction scores are written as *not measured* until Day 3 produces them |

## Pre-baked outputs

`prebaked_outputs/eval/` — real `run_eval.py` runs on the held-out 20
for every model the week compares, and the notebook 06 output. Its
README says which is which and how to show a table without a model.

`prebaked_outputs/mock_erp/` — the mock ERP (Day 4 agent labs, Day 5
S26) walked end to end: every endpoint, the one write and its
read-back, every error path, as real request/reply pairs from a live
server. If the ERP will not start in the room, show this; if it does
start, `python -m services.mock_erp.tour` prints the same thing live.

## Keeping the cost model honest

Prices were verified 2026-09-22 (sources and how sure we are:
`cost_model.md`). Re-verify the week before the room; the Azure
OpenAI regional price is the one number we could only get from a
secondary source and is marked VERIFY in the sheet. Then:

```
python scripts/build_cost_model.py          # rewrites cost_model.xlsx, prints the worked example
python -m pytest tests/test_cost_model.py   # recalculates the workbook in Excel if installed
```
